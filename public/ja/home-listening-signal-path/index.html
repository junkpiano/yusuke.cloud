自宅リスニング環境の信号経路メモ

2026年8月2日 · Yusuke Ohashi | 言語:
  • 🇺🇸
  • 🇩🇪
  • 🇨🇳

Apple Music を聴いている環境で「設定が正しくないのでは」と気づいたのを機に、 デジタル音声がどこを通ってどう書き換わるのかを整理したノート。

0. 前提：うちの環境#

まず自分の構成を確認しておく。以降の説明はすべてこの構成が土台。

位置機材役割
音源Apple Music (Windows版)配信・再生アプリ
PCWindowsOSがオーディオを仲介する
変換Steinberg UR22mk2オーディオインターフェース
出力①Yamaha HS5パワードモニタースピーカー
出力②Sony MDR-900STモニターヘッドホン

各機材の位置づけ#

Steinberg UR22mk2 — オーディオインターフェース Steinberg は Yamaha 傘下のオーディオ機器・ソフトウェアメーカー（Cubase の開発元）。 UR22mk2 はそこの入門クラスの USB オーディオインターフェースで、 本来は録音用の機材だが、中身は要するに

  • DAC（デジタル → アナログ変換器）
  • ヘッドホンアンプ
  • ラインアウト

を1つにまとめた箱。PC 内蔵のサウンド機能より素性が良いので、 再生専用に使っても意味がある。24bit/192kHz まで対応。

Windows から使うには専用ドライバ Yamaha Steinberg USB Driver が必要で、 これが後述する設定の片方を握っている。

Yamaha HS5 — モニタースピーカー アンプ内蔵（パワードモニター）。UR22mk2 の MAIN OUT から直接繋ぐ。 フラット寄りで低域は控えめ。「気持ちよく聴かせる」より「粗が見える」設計。

Sony MDR-900ST — モニターヘッドホン 日本のスタジオの事実上の標準機。63Ω。 4〜8kHz が張り出した特性で、これも粗探し向けの音。

→ HS5 と 900ST はどちらも「モニター系」。 　 つまりこの環境は最初から「正確さ優先・快楽性は後回し」の性格になっている。 　 音が硬い・疲れると感じてもそれは故障でも設定ミスでもなく、設計通り。

1. デジタル音声の基礎#

音は空気の圧力変化（連続的なアナログ波形）。 これをコンピュータで扱うため、一定間隔で波形の高さを測って数値の列にする。

  • サンプルレート — 1秒間に何回測るか。単位 Hz
    • 44,100Hz（CD規格）／48,000Hz（映像系）／96kHz／192kHz
  • ビット深度 — 1回の測定値を何段階で表すか
    • 16bit = 65,536段階／24bit = 約1,677万段階

配列で言えば、サンプルレートが要素数、ビット深度が1要素の型の精度。

なぜ 44.1kHz なのか#

標本化定理（ナイキスト＝シャノン）： サンプルレートの半分未満の周波数までしか正確に記録できない。

人間の可聴域上限が約20kHz → 2倍で40kHz必要 → アンチエイリアスフィルタの余裕を足して44.1kHz。

つまり 44.1kHz は妥協値ではなく、可聴域を記録するのに理論上十分な値。 ここは重要で、「数字が大きいほど良い」という直感がそのまま通用しない領域。

2. うちの信号経路#

Apple Music
      │  ← 音源自体のレート（例: 44.1kHz）
      ▼
Windows オーディオミキサー
      │  ← 「既定の形式」のレートに強制変換
      ▼
Yamaha Steinberg USB Driver
      │  ← ドライバ設定のレートに再度変換されうる
      ▼
UR22mk2 内部の DAC
      │  ← デジタル → アナログ
      ▼
HS5 / 900ST

独立した設定が2箇所ある#

問題はここ。同じ「サンプルレート」という設定項目が、別々の場所に2つ存在する。

場所設定箇所
Windows 側サウンド設定 → デバイスのプロパティ → 詳細 → 既定の形式
ドライバ側Yamaha Steinberg USB Driver コントロールパネル → Sample Rate

この2つが違う値だと、不要なサンプルレート変換 (SRC) が発生する。

3. 変換を避ける理由#

SRC は、既存のサンプル点から存在しない中間の点を補間で作る処理。

44.1kHz → 48kHz は整数比ではない（147:160）ので、 元のサンプル点がそのまま残らず、全部が再計算される。

44.1 → 48 → 44.1 と往復すれば、この処理が2回走る。 劣化自体は微小。問題はそれをやって得るものが何もないこと。

デジタル領域では「何もしない」のが最高品質。 目指す状態を ビットパーフェクト（元のバイト列が無加工でDACに届く）と呼ぶ。

4. 排他モードと、Apple Music の制約#

OSのミキサーをバイパスして、アプリが直接デバイスへ出力する仕組みがある。

方式説明
ASIOSteinberg が策定した規格。低レイテンシ。DAW用途の標準
WASAPI 排他Windows標準。ミキサーを迂回
WASAPI 共有通常モード。ミキサー経由・強制リサンプリング

※ ASIO が Steinberg 規格なのは偶然ではなく、UR22mk2 のドライバは当然 ASIO 対応。 　 ただし対応しているのはドライバ側で、使うかどうかはアプリ次第。

ここが今回の肝#

Apple Music (Windows版) は ASIO も WASAPI 排他も使えない。

→ 常に共有モード。ミキサー経由は避けられない。

→ したがって対策は「バイパスする」ではなく、 　 全段のレートを揃えて、変換が実質発生しない状態を作ること。

参考：他環境の挙動

  • foobar2000 / JRiver → ASIO・WASAPI排他対応、曲ごとに自動追従
  • Apple Music (macOS) → Audio MIDI設定を手動変更する必要あり
  • iOS → OSが曲のレートに自動追従（一番素直）

5. Apple Music の音質階層#

今回まず判明したのが、Lossless audio が Off になっていたこと。 つまり AAC 256kbps を聴いていた。

設定形式最大スペック
High QualityAAC 256kbps非可逆圧縮
LosslessALAC24bit / 48kHz
Hi-Res LosslessALAC24bit / 192kHz
  • ALAC = Apple Lossless Audio Codec。可逆圧縮（ZIPと同じ発想）。 展開後のデータは元とビット単位で完全一致する
  • カタログの大半は 16bit/44.1kHz。Hi-Res 音源は一部のみ
  • 「Hi-Res には外付けDACが必要」という警告 → UR22mk2 がその外付けDAC。 Bluetooth や内蔵スピーカーの人向けの定型文なので、そのまま進めてよい

6. 実際にやった設定#

方針：44.1kHz 固定#

カタログの大半が 44.1kHz なので、ここに合わせれば大多数の曲で変換ゼロ。

96kHz に固定すると 44.1kHz の曲が全部アップサンプリングされる。 アップサンプリングは情報を増やさない（存在しない点を補間するだけ）ので、 理論上のメリットがない。

手順#

  1. Yamaha Steinberg USB Driver コントロールパネル → Sample Rate = 44.1kHz
  2. Windows サウンド設定 → UR22mk2 のプロパティ → 詳細 → 既定の形式 = 24bit, 44100Hz
  3. 「オーディオの強化」「空間サウンド」をオフ
  4. Apple Music のイコライザ・サウンドチェックをオフ
  5. Windows の音量は100%固定。音量調整は UR22mk2 のノブで

5番目の理由#

デジタル音量調整はビット深度を削る。 50%に絞る ≒ 約1bit分の情報を捨てる。 UR22mk2 のノブはアナログ段なので、デジタルデータは無傷のまま。

UR22mk2 固有の注意#

  • MIX つまみを DAW 側に振り切る。INPUT 寄りだと入力端子の無音ノイズが混ざる
  • GAIN は絞っておく（再生専用なら入力は使わない）
  • HS5 へは MAIN OUT（TRSバランス）から。HS5 側 LEVEL は -10dB 前後にして、 音量調整は UR22mk2 の OUTPUT ノブに一本化する

7. 効果の優先順位（自戒）#

この環境で音質への寄与度を並べると、実際にはこうなる。

  1. HS5 の設置 — 壁から20〜30cm離す、ツイーターを耳の高さ、インシュレーター
  2. 部屋の音響 — 反射、定在波
  3. 900ST のイヤーパッド状態 — 潰れると高域が刺さり低域が抜ける。交換2千円程度
  4. 音源の品質 — AAC 256k か Lossless か ← 今回 Off だったのを修正
  5. サンプルレート設定 ← 今回調べた内容
  6. DAC・アンプの銘柄差

上位ほど支配的で、差は桁で違う。

5番目を正しくするのは「正しくない状態を放置しない」ためであって、 劇的な変化を期待するものではない。 AAC 256kbps と Lossless の差ですら、この環境で判別できたら上出来。

機材を買い足す前に、1〜3 をやる。 これが結論。

補足：エンジニア的な言い換え#

整理すると、やっていることはこう。

  • ALAC ファイルを展開 → PCM サンプル列（バイト列）
  • これが一切変更されずに UR22mk2 の DAC に到達する状態が「ビットパーフェクト」
  • SRC・デジタル音量調整・EQ・エフェクトは、いずれもこのバイト列を書き換える処理
  • 目標は「読み出したバイト列を、そのまま渡す」

ストリームをパススルーする際に、 余計なエンコード変換を挟まないようにするのと同じ話。 Windows のミキサーは、明示的に迂回しない限り必ず介入してくる中間層で、 Apple Music からはその迂回ができない。 だから「介入させないよう入出力の型を揃える」というのが今回の対処。
